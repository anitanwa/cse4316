\section{Introduction}
This SRS specifies \productname, an on-premises service that digitizes handwritten
numeric fields on scanned forms. It follows ISO/IEC/IEEE 29148:2018 \cite{ISO29148}.
\subsection{Purpose}
Agreed requirements baseline between Team Perceptron and the records office.
\subsection{Scope}
The system shall ingest scanned forms, segment numeric fields, recognize handwritten
digits with calibrated confidence, auto-accept high-confidence results, route
low-confidence fields to human review, and export verified structured data.
Free-text (non-numeric) recognition is out of scope.
\subsection{Product Overview}
\subsubsection{Product Perspective}
A containerized service on sponsor-provided on-prem infrastructure, exposing a REST
API and a small review web UI; input is scanned images from the office's existing
scanner workflow. \subsubsection{Product Functions}
Ingestion \& preprocessing; field segmentation; digit recognition with confidence;
confidence-based routing; human review; verified export; audit logging.
\subsubsection{User Characteristics}
Data-entry clerks (review UI users) and an IT administrator (deploys/monitors).
\subsubsection{Assumptions \& Dependencies}
Scans $\geq$200\,dpi grayscale; consistent field layout per template; labeled
validation set from the sponsor; on-prem GPU/CPU inference host.

\section{External Interface Requirements}
\subsection{EI-01: Ingestion API}
\req{The system shall accept form images via an authenticated REST endpoint
(\texttt{POST /forms}) as multipart PNG/TIFF and return a job identifier.}
{The office's scan workflow must submit images programmatically.}
{Sponsor IT.}{Critical}{Test --- submit images, verify job id and status.}
{On-prem network only.}{IETF RFC 9110 (HTTP), RFC 8259 (JSON).}

\section{Functional Requirements}
\subsection{FR-01: Field segmentation}
\req{For a known form template, the system shall locate each numeric field and
produce a per-field digit-crop set.}
{Recognition operates on isolated fields, not whole pages.}
{Team.}{Critical}{Test --- IoU of detected vs.\ ground-truth field boxes $\geq$0.9.}
{Depends on consistent template layout.}{None.}
\subsection{FR-02: Digit recognition with confidence}
\req{The system shall recognize the handwritten digit string in each field and
attach a calibrated confidence to each field value.}
{Confidence drives auto-accept vs.\ review routing.}
{Sponsor; team.}{Critical}{Test --- accuracy and calibration on the validation set.}
{Model runs on the on-prem host within latency budget (PE-01).}{None.}
\subsection{FR-03: Confidence-based routing}
\req{Fields with confidence $\geq$ the configured threshold shall be auto-accepted;
all others shall be placed in the review queue.}
{Keeps a human check exactly where the model is unsure.}
{Sponsor.}{Critical}{Demonstration --- fields route per threshold.}
{Threshold configurable by admin.}{None.}
\subsection{FR-04: Human review}
\req{A reviewer shall, through the web UI, see the field crop and proposed value,
and confirm or correct it; the decision shall be recorded with the reviewer id.}
{Auditable human oversight of uncertain fields.}
{Sponsor.}{Critical}{Demonstration --- review and correct a queued field.}
{Review UI runs in the office browser.}{None.}
\subsection{FR-05: Verified export \& audit log}
\req{The system shall export verified records (form id, field, value, source:
auto/reviewed) and retain an immutable audit log of every field decision.}
{Downstream systems consume clean data; disputes require an audit trail.}
{Sponsor.}{High}{Test --- export matches decisions; log entries immutable.}
{Export format agreed (CSV/JSON).}{None.}

\section{Usability Requirements}
\subsection{US-01: Efficient review}
\req{A clerk shall review and clear a queued field in under 10 seconds median
across 50 fields, using only keyboard confirm/correct.}
{Review throughput determines the net labor saving.}
{Sponsor.}{High}{Test --- timed review sessions.}{Readable crops in the UI.}
{WCAG 2.2 AA.}

\section{Performance Requirements}
\subsection{PE-01: Throughput \& latency}
\req{The system shall process at least 5 pages/second and return per-page results
within 2\,s (95th percentile) on the on-prem host.}
{Must keep up with the office scan volume.}
{Sponsor.}{High}{Test --- load test at target volume.}{Bounded by host hardware.}{None.}
\subsection{PE-02: Field accuracy}
\req{Auto-accepted fields shall have $\leq$0.5\% error, and end-to-end field
accuracy (after review) shall be $\geq$99.5\%.}
{Auto-accept must be safer than manual keying; the whole point is fewer errors.}
{Sponsor.}{Critical}{Analysis --- evaluate on the labeled validation set.}
{Requires representative validation data.}{None.}

\section{Security \& Privacy Requirements}
\subsection{SE-01: On-prem data handling}
\req{All form images and extracted data shall remain on sponsor-approved on-prem
infrastructure; no data shall egress to external services.}
{Form data may contain regulated PII.}
{Sponsor policy.}{Critical}{Inspection --- data-flow and egress review.}
{No cloud inference in prototype.}{None.}
\subsection{SE-02: Authenticated access}
\req{All API and review-UI access shall require authentication; every field
decision shall be attributable to an identified user or the automated pipeline.}
{Accountability and audit integrity.}
{Sponsor; team.}{High}{Test --- unauthenticated access refused; decisions attributed.}
{On-prem identity provider.}{NIST SP 800-63B (guidance).}

\section{Maintenance \& Support Requirements}
\subsection{MS-01: Model \& data versioning}
\req{Each deployed model shall be identified by a version and the dataset hash it
was trained on, recorded with every prediction it makes.}
{Reproducibility and rollback when a model regresses.}
{Team.}{Moderate}{Inspection.}{Version metadata stored with results.}
{ISO/IEC 25010:2023 (analysability) \cite{ISO25010}.}

\section{Other Quality Attributes}
\subsection{QA-01: Replaceable model}
\req{The recognition model shall be replaceable via configuration without code
changes to preprocessing, routing, or the API.}
{Lets the model improve as more real data is labeled.}
{Team.}{Moderate}{Inspection --- interface review.}{Defined model interface.}
{ISO/IEC 25010:2023 (modularity) \cite{ISO25010}.}
